## Follow-up 6 (same day): the app's hotel booking follows the website's rules
- Comparison with the aggregators found the older app API (`/api/hotels`, `POST /api/hotel-reservations`) bypassed
  the website's booking service: it listed hotels still waiting for approval, accepted `cash`, skipped the GST total,
  the unpaid hold and the stay limits, and showed each hotel owner's account record publicly.
- Now: browse shows bookable hotels only and no owner record; booking goes through HotelBookingService (online or
  wallet only, GST total, unpaid hold, one room type per booking); new `POST /api/hotel-reservations/{id}/pay` gives
  the Razorpay order (webhook confirms, as on the website). Both website and app refuse a past check-in or one beyond
  the booking window, and say "Hotels not available here" before anything else when the module is off.
- "Local ID accepted" added to the default facilities list. If Hotel Settings → Facilities was already saved, add it
  there by hand (one line).
- No migration, no build. Worker restart: yes.
