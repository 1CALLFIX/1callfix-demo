# Credentials Checklist

Generated by inspecting `config/services.php`, `config/mail.php`, and the
adapter classes that actually consume each value. Names and formats below
are copied verbatim from the code — never guessed. **No secret values are
recorded anywhere in this document**, only variable names and current
present/blank/missing status on the production server.

Every optional integration in this codebase follows the same pattern: a
`*_DRIVER` config value selects between a real adapter and a `log`
(no-op/fallback) adapter, bound in `app/Providers/AppServiceProvider.php`.
Leaving a driver at `log` is a safe, intentional default — the feature
degrades to logging instead of failing loudly, and nothing else breaks.

---

## 1. Mail

**Driver selector:** `MAIL_MAILER` (`config/mail.php` → `'default'`).
Not part of the driver/log-fallback pattern above — this is core Laravel
mail config, always in effect.

| Variable | Format | Required when |
|---|---|---|
| `MAIL_MAILER` | one of `smtp`, `ses`, `postmark`, `resend`, `sendmail`, `log`, `array` | always (selects transport) |
| `MAIL_HOST` | hostname/IP string | `MAIL_MAILER=smtp` |
| `MAIL_PORT` | integer (e.g. `587`, `465`, `2525`) | `MAIL_MAILER=smtp` |
| `MAIL_USERNAME` | raw string | `MAIL_MAILER=smtp` |
| `MAIL_PASSWORD` | raw string | `MAIL_MAILER=smtp` |
| `MAIL_SCHEME` | `smtp` / `smtps` / `null` — **this is the encryption selector**, not `MAIL_ENCRYPTION` (that var does not exist in this codebase's `config/mail.php`) | `MAIL_MAILER=smtp`, optional |
| `MAIL_FROM_ADDRESS` | email address | always (defaults to `hello@example.com` if unset) |

**Where to get it:** your SMTP provider's dashboard (e.g. Postmark →
Servers → API Tokens for `MAIL_PASSWORD` if using Postmark's SMTP,
or your mailbox provider's SMTP credentials page).

**What breaks if missing/wrong:** With `MAIL_MAILER=log` (the
`.env.example` default), nothing breaks — mail is written to the log
instead of sent. If `MAIL_MAILER=smtp` but host/port/credentials are
wrong, outgoing mail (password resets, notifications, booking
confirmations) fails at send time with a caught transport exception —
the app itself does not crash, but users silently stop receiving email.

## 2. Razorpay (payments)

Consumed by `app/Services/RazorpayService.php`,
`app/Services/Payments/RazorpayWebhookHandler.php`,
`app/Services/CancellationService.php`, `PayoutService.php`,
`Plans/RenewalService.php`, `Operations/ReconciliationService.php`.

| Variable | Format | Where in dashboard |
|---|---|---|
| `RAZORPAY_KEY_ID` | raw string, e.g. `rzp_live_xxxxxxxx` (prefix reveals test/live mode) | Razorpay Dashboard → Settings → API Keys |
| `RAZORPAY_KEY_SECRET` | raw string | same screen, shown once at generation |
| `RAZORPAY_WEBHOOK_SECRET` | raw string | Razorpay Dashboard → Settings → Webhooks → (your webhook) → Secret |

**What breaks if missing:** `RazorpayService::isConfigured()` returns
`false` when any of the three is blank, and the app deliberately treats
the properties as nullable so *construction* never crashes (a past bug —
cancelling an unpaid booking used to crash hard when this was a
non-nullable `string`). Actually calling Razorpay's API without real
credentials fails loudly with a `RuntimeException` from the
`!$response->successful()` check — payment/payout/refund/webhook
verification flows fail explicitly, they don't fail silently.

## 3. Push notifications — Firebase Cloud Messaging (FCM)

Driver selector: `PUSH_DRIVER` (`log` default, `fcm` for real).
Consumed by `app/Notifications/Adapters/FirebaseFcmPushAdapter.php`.

**Note:** the actual variable names are `FCM_*`, not `FIREBASE_*`.

| Variable | Format | Where in dashboard |
|---|---|---|
| `PUSH_DRIVER` | `log` or `fcm` | n/a — set to `fcm` to activate real push |
| `FCM_PROJECT_ID` | raw string, the Firebase project ID | Firebase Console → Project Settings → General → "Project ID" |
| `FCM_CREDENTIALS_PATH` | absolute file path to a service-account JSON file on the server (never committed to the repo) | Firebase Console → Project Settings → Service Accounts → "Generate new private key" (downloads a `.json` file — upload it to the server, then point this var at its path) |
| `FCM_CREDENTIALS_JSON` | the same service-account JSON's **full content**, as a single env value — alternative to `FCM_CREDENTIALS_PATH` for hosts without a reliable persistent file path | same download as above; only one of `FCM_CREDENTIALS_PATH` / `FCM_CREDENTIALS_JSON` is needed, not both |

**What breaks if missing:** With `PUSH_DRIVER=log`, nothing breaks —
push "sends" just get logged. With `PUSH_DRIVER=fcm` but
`FCM_PROJECT_ID` blank, or both credentials vars blank, `send()` logs an
error and returns `false` per-call — push notifications silently stop
delivering, nothing crashes app-wide.

Explicitly **not reused**: a historical Firebase project's embedded
credentials found in an old data dump — already expired, and would not
be reused across environments even if valid. A fresh service-account key
must be generated for this app's own Firebase project.

## 4. SMS — Arkesel

Driver selector: `SMS_DRIVER` (`log` default; `arkesel`/`msg91`/`gatewayapi`
are the real options — **Arkesel is the confirmed provider** for this
business per the adapter's own docblock; msg91/gatewayapi exist as
built-but-unconfirmed alternatives).

| Variable | Format | Where in dashboard |
|---|---|---|
| `SMS_DRIVER` | `log`, `arkesel`, `msg91`, or `gatewayapi` | n/a — set to `arkesel` to activate |
| `ARKESEL_API_KEY` | raw string | Arkesel Dashboard (sms.arkesel.com) → API section → API Key |
| `ARKESEL_SENDER` | raw string, the approved sender ID | Arkesel Dashboard → Sender IDs (must be pre-approved before use) |

**What breaks if missing:** With `SMS_DRIVER=log`, nothing breaks. With
`SMS_DRIVER=arkesel` but either var blank, `ArkeselSmsAdapter::send()`
logs an error and returns `false` — SMS/OTP delivery silently fails
per-call, nothing crashes app-wide.

*(Not in the original grep list for this checklist — `SMS_DRIVER` /
`ARKESEL_*` surfaced from reading the full `config/services.php` and are
included here since they're a real, code-present external integration
point.)*

## 5. AI narrative phrasing — Anthropic

Driver selector: `AI_DRIVER` (`log` default; `anthropic` for real).
Consumed by `app/Services/Ai/AnthropicNarrativeAiAdapter.php`, used by
`OperationalInsightsService` and `DailyInsightsService` to rephrase
already-computed facts into prose — never to decide the facts themselves.

| Variable | Format | Where in dashboard |
|---|---|---|
| `AI_DRIVER` | `log` or `anthropic` | n/a — set to `anthropic` to activate |
| `ANTHROPIC_API_KEY` | raw string, `sk-ant-...` | console.anthropic.com → Settings → API Keys → Create Key |
| `ANTHROPIC_MODEL` | raw string, model ID (defaults to `claude-opus-5` if unset) | n/a — optional override |
| `ANTHROPIC_TIMEOUT_SECONDS` | integer (defaults to `10` if unset) | n/a — optional override |

**What breaks if missing:** With `AI_DRIVER=log`, nothing breaks — no
network call is made at all. With `AI_DRIVER=anthropic` but
`ANTHROPIC_API_KEY` blank, `summarize()` logs a warning and returns
`null` — every caller already treats `null` as "fall back to the plain
fact list", so the dashboard just shows deterministic facts instead of
AI-phrased prose. Fails closed on any HTTP error, timeout, malformed
response, or refusal too — never throws, never breaks the screen it
decorates.
