## Open items this matrix surfaces, not silently absorbed elsewhere

1. Service start/completion OTP delivery-to-customer gap — see `OTP_ARCHITECTURE.md`'s recommendation (a notification send inside `AcceptBookingAction`, not yet added).
2. Standalone phone-verification-without-login was never requested and wasn't built — if a future flow needs "verify this phone number" independent of issuing a session (e.g. verifying a second contact number on a profile), `OtpService` already supports it via a new `purpose` value; only a new controller action would be needed, not a new engine.
